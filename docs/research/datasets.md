## Code / on-disk format descriptions found

- **eraw1am/Honeywell-NVR-Filesystem-Tools** https://github.com/eraw1am/Honeywell-NVR-Filesystem-Tools (created 2026-04-07, 8 KB, 3 files; almost certainly the code companion to Yoon & Hwang arXiv:2605.07430 - Korean comments). No images in repo, but the code documents the **Honeywell NVR disk layout**:
  - Start area: sectors 0-39 (20 KiB), fixed.
  - Partition 1 (video): starts at sector 40, size variable (137 GiB on a 160 GB disk = sectors 40..287,415,983; 221 GiB on a 250 GB disk = 40..463,231,343).
  - Partition 2: fixed 10 GiB immediately after partition 1.
  - Unpartitioned: fixed 2 GiB at end of disk.
  - Video carving starts at absolute offset 0x80005000 (= 2 GiB + 20 KiB); video chunks delimited by runs of >= 20 zero bytes ("End of Data" in paper). Author's test images were named `07_2510151911_sample.dd` and `09_delete_format.dd` (not published).

- **Honeywell 35 Series NVR User Guide** (rev G, 2025-08-27, 222 pp, 16 MB): https://prod-edam.honeywell.com/content/dam/honeywell-edam/hbt/en-us/documents/manuals-and-guides/user-manuals/hon-ba-security-800-27009-g-35snvr-plusnvr-ug-20250827.pdf?download=false
  - **HDD encryption option at disk-format time**: "Encryption key is used to keep the data safety in the disk ... If the encrypted disk [is] installed in another NVR, users need to input the same encryption key ... If the encryption key is error, the disk must be formatted" -> a seized HN35 disk may be encrypted (forensic caveat; ask for the key at seizure). Also "Backup failed: abnormal encryption chip ... error happens for encrypted private backup" (encrypted proprietary backup format exists).
  - Exports: "There is no media player, the file support VLC player to play" (standard container). P2P + MAXPRO Cloud (mymaxprocloud.com) + HSV client.
  - Firmware file name pattern (from Honeywell HDD guide / search snippet): `HON_Honeywell_Series35_HN35XX0XXXX_1_HC1.22.1.42.20220420.bin` - no public download found (Honeywell downloads page has no firmware links; partner portal). The `<OEM>_<Brand>_<Series>_..._<ver>.<date>.bin` pattern hints at a white-label ODM but the ODM was NOT identified.
  - DVR Examiner maps older Honeywell DVRs to "IFS" and "A5" filesystems (see below). IPVM (secondary): Honeywell relabelled Dahua for its Performance Series until April 2022.

- **Downloaded & unpacked** `TP-Link_VIGINVR1008HV2_240119_cc1d1` -> `cc1d1c847941544384c1cc7c7780052b.zip` (16,970,556 B) -> `VIGI NVR1008H(UN)_V2.0_240119/nvr1008hv2_en_1_0_7_up_boot_24011951953-signed.bin` (16,253,440 B). NOT encrypted: TP-Link signed header (0x000-0x3FF), uImage "Linux-4.9.84" at 0x400, **SquashFS 4.0 xz at 0x18A600** (3833 inodes). SoC = SigmaStar/MStar (mi_sys.ko, mhal.ko). Extracted with PySquashfsImage (pip). Local copy: `research/fw_vigi/rootfs/`.
- **What the firmware reveals about the VIGI on-disk format ("TPFS")** - from `/usr/lib/liblayouthddb.so` (546 KB) and `/usr/lib/libstorage.so`:
  - Library variable `tpfs_ver` -> TP-Link's layout is called **TPFS**. This is very likely the "TPFS" in UFS Explorer's supported-CCTV-FS list.
  - Disk format-tag / magic string: **"TP-Link Corporation Limited, NVR FOR VERSION %d.%d.%d"** (literal "... NVR FOR VERSION 2.2.3" present). Code: "Check Format Tag, Disk Format Tag is %s Now Format Tag is %s", "Disk %d ReWrite TP_NVR_TAG". -> use as vendor signature.
  - Partitioning by in-house `tp_fdisk` (also `tp_fdisk_for_swap`, `tp_mkswap` -> a Linux swap partition "SWAPSPACE2" on the HDD; `tp_fdisk_for_raid`).
  - Data partition = **ext4**: `mkfs.ext4 -i 1048576 -G 128 -N %d -q %s`; mounted at `/mnt/disk/disk_%d`; contains `sys.bin` and pre-allocated **zone files** ("Total create %d zone file", "open_zone_file Zone %d"). There is also a `rawDiskLayout` variant (raw zones, no ext4) with default DB size 64/128/256 MB chosen by disk size.
  - Index = **SQLite** (PRAGMA journal_mode=WAL; TP-modified sqlite: sqliteTpFileInit, setTpFileKeyByFileTpFs, TP_ENCRYPT_NULL; backup DB `bk_db_file_name`; "DB Area" with journal & restore). Tables: tEventInfo, tSubEventInfo, tZoneInfo, tLayVerInfo, tAudioInfo, tPictureInfo, tSmartPicInfo, tSmartd, tMetadata, tSlogInfo, tSlogExtraInfo, tFaceGallery, tFaceIdObjr, tFaceEventInfo, tTagInfo. Zone table columns: zoneId, blockId, channelId, dataType, status, startTime, endTime, curOffset, lockFlag, writeTimes, dataBlob, dataIndexCount. Event table: eventId, startTime, endTime, zoneId, offset, len, frame_cnt. Queries select channelId, eventType, eventId, startTime, endTime, mainGopLen, subGopLen, audioGopLen, lockFlag.
  - Video stored as GOPs inside zones ("zone%d find gop@%d count:%d time[..] len:%d i_f%d"); a `GOP_SIZE_TABLE` keyed by version. Deletion = SQL `DELETE FROM ... WHERE zoneId == ...` -> deleted rows may survive in SQLite freelist/WAL (forensic opportunity).
  - Export filename pattern (from `/bin/nvrcore`): `ch%02d_YYYYMMDD_HHMMSS_HHMMSS.mp4` (and `...topspeed.mp4`).
